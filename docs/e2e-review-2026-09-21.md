# They Will Kill You acceptance review — 2026-09-21

The running full-movie jobs and an isolated excerpt of the same source were reviewed.
The source movie and the original encoding configurations were preserved. No screenshots
were uploaded, no torrent was announced, and no release was published.

## Running movie jobs

- x264: `bee125cc-cc85-4aaf-be4f-54beb31cceb0`
- x265: `54e4173f-b8a2-4560-8520-a15eb822b7d0`

`audio_comparison` from the required properties. The corrected agent was built and

schema requires a coordinated API/worker update after the existing encodes finish.
The updated frontend supports this older API and explains when the separate limits
are unavailable. The isolated current-code test uses the new limits: **one encoding/CRF
task and three other tasks**.

## Actual-media acceptance run

The test input is a 45.086-second MKVToolNix excerpt at approximately 00:23:20 from
`They Will Kill You-SEG_FPL_MainFeature_t00.mkv`, retaining all three AC-3 audio tracks
and three PGS subtitle tracks. It contains **1,081 frames**, at 1920 × 1080 and
24000/1001 fps. The native crop produces 1920 × 872 output.

Test profiles preserve the project's codec settings but use `fast` presets and
bounded encoder threads. Both use real two-pass 6 Mbps encodes. CRF Studio runs two
2-second samples; local speech transcription and actual agent reviews are enabled,
with a two-round audio limit. Screenshot sampling uses 24 candidate windows, a
one-second spacing policy suitable for the excerpt, and one final pair per codec.
These are test settings, not a quality assessment of the full-movie release presets.

The harness exercises the actual handlers and API gates, without substituting media
or agent results: scan, parallel track review and CRF analysis, early release-draft
saving, two-pass encoding, decoded-frame/timestamp validation, cached extraction
reuse, PGS cropping, remuxing, verified B-frame sampling, live agent screenshot
selection, confirmation/rendering, and local BBCode/NFO/MD5/torrent generation.

The isolated storage and database are under `data/e2e-review/`. Releases are explicitly
named `E2E.TEST.They.Will.Kill.You...` and use a nonfunctional test tracker URL.
Full job records are saved in `data/e2e-review/results/`; artifacts are under
`data/e2e-review/artifacts/`. The harness is `tests/container_movie_e2e.py` and must
be run as `python -m tests.container_movie_e2e` with isolated `/review` storage.

## Frontend review and fixes

Login, Dashboard, New Job, Queue, Overview, Tracks, CRF, Encode, Screenshots,
Release, and Artifacts were reviewed at desktop (1440 px), tablet (900 px), and
mobile (390 px) widths. All **33 page/viewport checks** passed against the live
frontend, and another 33 passed against completed test jobs: no page-width overflow,
no JavaScript errors, and the current tab remains visible. Checks cover both processing
and completed states; off-screen tabs stay inside their horizontal navigation scroller.

- Existing failed, cancelled, or running track reviews no longer restart merely
  because the Tracks page is opened or refreshed.
- The overview puts active tasks first and describes independent track-review
  failures accurately. The full workflow remains available in an expandable view.
- Dashboard attention counts include track-review failures alongside an active
  encode, and completed reviews waiting for track choices.
- Headers identify the codec profile, and mobile navigation reveals the active tab.
- Automatic logs follow the current page; queue progress links open the correct page.
- Track confirmation no longer overlaps rows. Audio comparisons use responsive columns.
- Full encoding settings use a compact grid; long commands remain expandable.
- New Job handles custom profile names instead of crashing on missing hardcoded names.
- Artifacts are searchable, filtered, paginated, and ordered with recent files first.
  Completed jobs initially show release files. Full paths remain expandable, and
  small files display KB or bytes instead of `0.0 MB`.
- Screenshot settings and completed agent responses are expandable. Final screenshots
  do not show irrelevant selection controls. Release previews are immediately accessible
  after generation, with the edit form retained in an expandable panel.

Browser checks passed for real release text previews, artifact search and locations,
loaded full-resolution comparison dialogs, mobile layouts, custom track names/flags,
queue-limit persistence, and compatibility with the old queue API. Captures are kept
under `data/e2e-review/ui/`. The final browser interaction run also exercised the
completed x265 release. Temporary test services were removed after verification;
results and generated test bundles remain available locally.

Relevant automated checks: **118 Python tests**, **26 frontend unit tests**,
TypeScript/Vite build, formatting/lint, and browser interaction suites passed.
The existing dependency deprecation warnings and Vite bundle-size advisory remain.

## Scope limits

A complete excerpt run exercises the real pipeline but does not certify the final
full-length encoded movies. Their long-running two-pass encodes must finish before
full-duration validation, final screenshot choices, and real release completion can
be confirmed. Test releases intentionally omit IMDb lookup and external uploads.
